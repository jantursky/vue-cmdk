---
title: Search
description: How the query matches and ranks rows, and how to swap in your own matcher.
---

The query matches as a plain substring anywhere in the label, keywords, or hint. Case doesn't matter. There's no fuzzy matching, on purpose: fuzzy search returns something for every query, so a typo gets you a confident list of wrong answers.

## Ranking

Best first:

1. the label starts with the query
2. the label contains it (earlier positions rank higher)
3. a keyword contains it
4. the hint contains it (earlier positions rank higher)

Groups are sorted by their best match, so the group holding the top hit comes first. With an empty query there is nothing to rank, and groups follow the `group-order` prop, or the order they first appear in `commands`.

A non-empty query draws at most 40 rows. Change that with `max-results`. The footer shows "first 40 of 112" when the list was capped.

## Typographic marks

Curly quotes, dashes and similar characters match their keyboard forms, so typing `what's` finds `What’s new`, and `light - dark` finds `Light — dark`.

## Highlighting

Matched text is wrapped in `<mark data-cmdk-highlight>`. Keywords only show when they matched, as small chips after the label, at most three per row.

If you render rows yourself, the `CommandHighlight` component draws the same marks from a row's segments:

```vue
<CommandHighlight :segments="label" />
```

## A custom matcher

Pass `filter` to replace matching and ranking. It returns `null` for no match, or a score where lower is better:

```ts
import type { FilterFn } from '@jantursky/vue-cmdk'

const filter: FilterFn = (command, needle) => (command.label.startsWith(needle) ? 0 : null)
```

Highlighting still uses the built-in substring match, so a filter that matches in other ways shows rows without marks.
